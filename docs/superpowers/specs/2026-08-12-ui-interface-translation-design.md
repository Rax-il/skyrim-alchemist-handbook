# Перевод интерфейса приложения — дизайн

Дата: 2026-08-12

## Контекст

С момента `docs/superpowers/specs/2026-08-10-i18n-storage-design.md` (планы A→B1→B2a→B2b→B3+B4) и механизма
перевода описаний ингредиентов приложение полностью локализовано по
*контенту* — названия/свойства/описания 178 ингредиентов доступны на всех
9 поддерживаемых языках через `component_translations`/`property_translations`
и `seed_description_translations.rs`. Но сам интерфейс приложения (меню,
кнопки, лейблы, тултипы, диалоги) захардкожен по-русски во всех 8
компонентах — при переключении языка в Настройках меняется только
отображаемый контент, а не обвязка вокруг него.

Мотивация (сформулирована пользователем): если пользователь откроет
приложение не на родном языке, он может не найти пункт «Настройки», чтобы
переключить язык на свой. Значки меню (сделаны этой же сессией раньше,
см. `src/App.tsx` — карандаш/шестерёнка/дверь/вопросик у пунктов меню
«Файл»/«О программе») — первый шаг к интуитивности без текста. Перевод самого
интерфейса — следующий шаг. (Смена языка по умолчанию на английский для
новых установок — отдельная, более поздняя задача, здесь не решается.)

Существующий `language` state в `App.tsx` (введён в B3+B4, персистится
через `layout.rs`/`save_language`) уже управляет тем, на каком языке
загружается контент из бэкенда — интерфейс должен следовать за тем же
state, не заводить отдельный источник истины.

## Объём

Весь текст интерфейса разом, во всех 8 компонентах (`App.tsx`,
`EditorModal.tsx`, `SettingsModal.tsx`, `ControlPanel.tsx`,
`ThanksModal.tsx`, `AboutModal.tsx`, `BottomPane.tsx`, `HintIcon.tsx`) —
это меню, кнопки, лейблы, тултипы, диалоги, включая длинные тексты вроде
блока «О программе» и текста предупреждения при смене языка в Настройках
(ранее сознательно оставленного русским в B3+B4 — теперь этот пункт
закрывается). Плюс заголовок окна приложения (см. ниже).

Явно не в объёме: реквизиты/адреса доната в `ThanksModal` — это данные, не
текст интерфейса, не переводятся.

~90 строк с кириллицей на данный момент (примерный подсчёт по `grep`),
переводятся во все 8 не-ru языков.

## Механизм

**`react-i18next` + `i18next`**, а не самописный `t()`. Причина: среди
найденных строк есть склонение по числу («Найдено N комбинаций»,
«Свойство {i+1}») — у русского и польского сложные правила (05, 11-14 и
т.п.), у английского/китайского/японского — свои. i18next поддерживает
CLDR-правила плюрализации из коробки; самописный вариант потребовал бы
вручную писать и тестировать функции склонения для языков, которые никто
в проекте не знает на уровне грамматики — риск тонких ошибок.

Хранить строки в Rust/БД (по аналогии с `seed_description_translations.rs`)
не рассматривается: UI-текст статичен, не редактируется пользователем — в
отличие от контента, ему не нужна гибкость БД, а добавление IPC-запроса за
интерфейсными строками смешивает слой представления с уже нарочно
Tauri-агностичным `db.rs` (см. «Структура проекта» в `SESSION_NOTES.md`).

### Структура файлов и ключей

- `src/i18n/index.ts` — инициализация `i18next`, статический импорт всех 9
  JSON-ресурсов (один namespace, объём не требует ленивой загрузки).
- `src/i18n/locales/<lang>/translation.json`, `<lang>` = `ru`, `en`, `fr`,
  `de`, `it`, `es`, `pl`, `ja`, `zh-Hant` (тот же список кодов, что и
  `LANGUAGE_OPTIONS` в `lib/languages.ts`).
- Ключи вложены по компоненту, например `editorModal.saveButton`,
  `settingsModal.languageWarning.title` — совпадает со структурой
  компонентов, ключи легко найти по имени файла, исключает коллизии имён
  между компонентами.
- Строки со счётом используют встроенный плюрал-механизм i18next:
  `t('key', { count: n })` + ключи с суффиксами `_one`/`_few`/`_many`/
  `_other` в JSON (i18next сам выбирает нужный суффикс по CLDR-правилам
  текущего языка).
- `fallbackLng: "ru"` — если для нового ключа забудут добавить перевод на
  каком-то языке, показывается русский текст (ru — язык, на котором
  пишется весь новый UI-текст по умолчанию), а не пустой ключ/строка.

### Интеграция с существующим `language` state

`App.tsx` остаётся единственным источником истины для текущего языка
(persist через `layout.rs`, как сейчас). Новый `useEffect` на изменение
`language` вызывает `i18n.changeLanguage(language)` — тот же паттерн, что
уже используют эффекты, дёргающие `api.getProperties(language)` и т.п.
Компоненты переходят с захардкоженных строк на `useTranslation()` + `t()`.

**Заголовок окна** (`"Справочник алхимика"`, сейчас статично прописан в
`src-tauri/tauri.conf.json`) — тоже переводится. Это не React-текст,
поэтому не через `t()` напрямую в JSX: в том же `useEffect`, что вызывает
`i18n.changeLanguage`, добавляется вызов
`getCurrentWindow().setTitle(t('appTitle'))` из `@tauri-apps/api/window`
(уже используется в `App.tsx` для других целей).

## Авторство перевода

Все переводы — я (Claude), как и с описаниями ингредиентов. В отличие от
описаний (110 ингредиентов, отдельные батчи после отдельного захода на
сам механизм) здесь объём меньше (~90 строк) и решили делать весь объём —
и механизм, и контент — одним заходом, без разделения на код/данные по
разным сессиям. Внутри реализации перевод может по-прежнему добавляться
JSON-файл за JSON-файлом или компонент за компонентом — это уже деталь
плана, не дизайна.

## Проверка

- `npx tsc -b` + `npm run lint` (`oxlint`), как обычно для фронтенд-задач
  в этом проекте — нет автотестов на фронтенде.
- `cargo test --lib` не требуется — Rust-код не меняется (заголовок окна
  выставляется через JS `@tauri-apps/api/window`, не через Tauri config
  или команду).
- Ручная проверка: скриншот на нескольких языках — ru как есть, один
  «длинный» язык (de или pl, чтобы проверить переполнение кнопок/лейблов
  длинным текстом) и один нелатинский (ja или zh-Hant).
