# Справочник алхимика (версия на Tauri + React)

Переписано с egui/eframe на **Tauri 2 + React + TypeScript + Vite + Mantine**.
Вся бизнес-логика (SQLite-схема, поиск сочетаний/пар, миграции данных)
перенесена в `src-tauri/src/db.rs` **один в один** из прошлой Rust-версии —
это чистые функции над `rusqlite::Connection`, не завязанные на GUI, поэтому
их можно было скопировать почти без изменений. Поменялся только слой
интерфейса: вместо immediate-mode egui теперь веб-интерфейс на React,
который живёт в системном WebView (WebView2 на Windows) и общается с Rust
через `invoke()`.

## Структура проекта

```
src/                      — фронтенд (React + TS + Mantine)
  lib/api.ts               — типизированная обёртка над invoke()
  components/               — ControlPanel, TopPane, BottomPane, EditorModal
  App.tsx                   — сборка интерфейса, состояние приложения

src-tauri/                — бэкенд (Rust)
  src/db.rs                 — 1-в-1 из старого проекта: схема, поиск, CRUD
  src/seed_data.rs,
  src/rare_curios.rs,
  src/creations.rs          — данные (ингредиенты/свойства), тоже 1-в-1
  src/commands.rs            — #[tauri::command]-обёртки над db.rs для React
  src/lib.rs, main.rs        — инициализация приложения
  src/paths.rs               — alchemist.db и alchemist_settings.json кладутся
                                рядом с exe (портативность, как раньше)
  alchemist.db                — та же готовая база с картинками, что была у вас
```

## Что перенесено функционально

- поиск сочетаний по 4 свойствам (2–3 компонента, минимум 2 совпадения на
  свойство), фильтр "Все / Улучшения / Яды" — то же самое поведение,
  тот же алгоритм (`find_combinations` в db.rs не менялся);
- список компонентов найденного сочетания с чекбоксами и клиентской
  фильтрацией результатов (как в egui-версии);
- "Показать свойства" — список свойств + картинка/описание компонента;
- "Парные сочетания";
- окно "Редактировать базу": создание/переименование/удаление компонента,
  4 свойства, картинка (диалог выбора файла), описание, отслеживание
  несохранённых изменений с подтверждением при попытке уйти;
- сохранение раскладки (ширина левой панели, позиция разделителя между
  верхней и нижней панелью) и размера/позиции окна между запусками.

## Что стоит перепроверить при первом запуске

Я не смог собрать и запустить Tauri-приложение в этой песочнице — здесь
нет ни Rust, ни системных библиотек для WebView (только Node/npm). Поэтому:

- **Фронтенд** — я прогнал `tsc -b` и `npm run build`, компилируется и
  собирается без ошибок. Логику UI (стейт-машина топ/боттом-панелей,
  редактор) я тщательно сверил построчно с исходным `main.rs`/`editor.rs`,
  но живого клика мышкой по факту не было.
- **Rust-часть** — код я не компилировал (нет `cargo` в этой среде).
  Сигнатуры API `tauri-plugin-dialog` и `tauri-plugin-window-state`
  я перепроверил по актуальной документации v2, но при первой сборке
  возможны мелкие несостыковки версий (обычно чинится в одну строку —
  Rust-компилятор для таких вещей даёт очень точные сообщения об ошибке).
- Ручки перетаскивания (ширина панели, разделитель верх/низ) реализованы
  вручную через mousedown/mousemove — работать должны, но UX стоит
  сравнить с тем, что было в egui, и подправить чувствительность при
  необходимости.

Если что-то не соберётся с первого раза — пришлите мне текст ошибки
`cargo build`/`npm run tauri build`, разберём.

## Шаг 1. Установить инструменты (один раз)

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# Node.js 18+ и npm — если ещё не стоят
```

Системные зависимости для запуска/сборки Tauri **на Linux** (нужны только
для `npm run tauri dev` — посмотреть приложение живьём на Linux; для сборки
самого Windows-exe не нужны):
```bash
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
    libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

## Шаг 2. Установить зависимости проекта

```bash
npm install
```

## Шаг 3. Разработка (живой просмотр на Linux)

```bash
npm run tauri dev
```
Откроется окно с приложением, hot-reload фронтенда работает как обычно
в Vite.

## Шаг 4. Собрать .exe под Windows — два варианта

### Вариант А (рекомендуется): собрать прямо на Windows

Как и раньше с egui-версией, самый надёжный способ — поставить Rust и
Node на саму Windows-машину (или в CI на Windows-раннере) и собрать
штатно:
```powershell
rustup default stable-msvc
npm install
npm run tauri build
```
Готовый файл — `src-tauri/target/release/alchemist.exe`. Так как
`bundle.active` выключен в `tauri.conf.json` (см. ниже, почему), инсталлятор
не создаётся — просто портативный exe, ведёт себя один в один как раньше:
кладёте `alchemist.exe` и `alchemist.db` в одну папку — работает.

### Вариант Б: кросс-сборка с Linux

Здесь всё сложнее, чем было с чистым Rust-бинарником через
`x86_64-pc-windows-gnu` — Tauri тянет за собой WebView-обвязку (`wry`/`tao`),
которая под Windows завязана на MSVC, а не на mingw-gnu. Рабочий путь —
через **`cargo-xwin`** (эмулирует MSVC-линковщик и подтягивает нужные
заголовки/библиотеки Windows SDK автоматически, ничего скачивать вручную
не нужно):

```bash
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin
cargo install tauri-cli --version "^2"

npm install
npm run build                 # сначала собрать фронтенд (dist/)
cd src-tauri
cargo xwin build --release --target x86_64-pc-windows-msvc
```
Готовый файл — `src-tauri/target/x86_64-pc-windows-msvc/release/alchemist.exe`.

Если `cargo xwin` даст сбой (случается на некоторых версиях зависимостей
webview-стека — это известное больное место кросс-сборки Tauri, менее
стабильное, чем было у чистого egui/eframe) — не тратьте на это много
времени, переходите на вариант А (сборка прямо на Windows) или на GitHub
Actions с `windows-latest` раннером, где `npm run tauri build` работает
из коробки.

## Про базу данных

Как и раньше: `alchemist.db` (уже с 178 компонентами, 61 свойством и всеми
картинками) лежит в `src-tauri/`. После сборки скопируйте её рядом с
получившимся `alchemist.exe` — программа найдёт её по пути рядом с exe
(`paths.rs`, чуть надёжнее, чем прежний "рабочая директория процесса" —
теперь работает независимо от того, как именно запущен exe).
